# Proposal: move the template to pnpm 11.9.0

> **Status:** archived — 2026-11-14

## Why

The template pins pnpm 9.15.9: the `packageManager` field of the root `package.json`, the seven
`pnpm/action-setup` steps of `.github/workflows/ci.yml` and two CI snippets in `docs/`.
Certifipago runs this same stack on pnpm 11.9.0, and the owner decided that the template follows
(`docs/INIT_AND_HARNESS_PLAN.md`, "Open decisions" D-S6; Roadmap step 2.3: "`packageManager`,
lockfile, CI and `.npmrc` follow Certifipago's proven setup").

pnpm 11 reads its configuration differently from pnpm 9, observed on this tree under 11.9.0:

- it ignores the `pnpm` field of `package.json` and warns that `pnpm.overrides` and
  `pnpm.packageExtensions` were ignored, so the two `@types/react` overrides and the
  `@tanstack/react-query` peer extension would silently stop applying;
- it reads no `public-hoist-pattern` from `.npmrc` (`pnpm config get public-hoist-pattern`
  prints `undefined`), so the four hoist patterns there would stop applying;
- it fails the install with `ERR_PNPM_IGNORED_BUILDS` on every dependency build script it has
  not been told to allow; pnpm 9 ran seven builds without asking, from six package names
  (`@parcel/watcher`, `@sentry/cli` in two versions, `@swc/core`, `msw`, `sharp`, `unrs-resolver`).

The owner's words:

- 2026-11-13 (translated from Spanish): "apply the recommendations you mention"
- 2026-11-14 (translated from Spanish): "merge #8 and continue with the plan"

## What changes

- **The version.** `packageManager` becomes `pnpm@11.9.0+sha512.<hash>`, the hash Corepack
  verifies (the npm registry's integrity of the 11.9.0 tarball, and the value Certifipago pins).
  The `pnpm/action-setup` steps of `ci.yml` stop naming a version and read `packageManager`, as
  Certifipago's `ci.yml` does, so the next upgrade changes one line. The CI snippets in
  `docs/e2e.md` and `docs/responsive.md` follow.
- **The settings, in `pnpm-workspace.yaml`.** `overrides` and `packageExtensions` move there from
  the ignored `pnpm` field, unchanged. `publicHoistPattern` takes the four patterns of `.npmrc`,
  unchanged, so `node_modules` keeps the layout it has under pnpm 9. `allowBuilds` approves the
  six packages whose build scripts pnpm 9 ran. `shellEmulator: true` comes from Certifipago, with
  the reason it gives there: scripts written `VAR=value command` (`test:e2e:visual`,
  `test:e2e:visual:update`, `smoke:mobile-web`) run on Windows instead of failing in `cmd.exe`.
- **`.npmrc` is removed**, with its manifest claim: pnpm 11 reads none of its four lines, which
  now live in `pnpm-workspace.yaml`, and npm warns about the unknown key on every run.
- **The lockfile** is regenerated by `pnpm install` under 11.9.0 from the current one, not from
  scratch, so no direct dependency moves.
- **The docs** that name the pnpm version (`AGENTS.md`, `README.md`, the `/init` defaults in
  `docs/INIT_AND_HARNESS_PLAN.md`) name 11.

## Out of scope

- Certifipago: it is already on 11.9.0.
- The package-private `#src` aliases (Roadmap step 2.1), a parallel change.
- `@app/tooling` (Roadmap step 2.2).
- Certifipago's `nodeLinker: hoisted`, tried and left out. It keeps React Native's C++ object
  paths under the Windows `MAX_PATH` limit on a native build, but on this tree it changes what
  the mobile app ships: the root gets the web app's `@sentry/core` 10.61.0, so the hoisted linker
  nests a copy of 10.75.2 under each of the seven Sentry packages that need it, six of them in
  the bundle, and the Android bundle grows from 2,378 to 3,596 source modules (7 MB to 9.3 MB),
  all of the growth in `@sentry/core` and `@sentry/browser-utils`. A project that builds natively on Windows can take
  it once its Sentry versions agree.
- Certifipago's other `pnpm-workspace.yaml` entries: its security `overrides` answer advisories
  in its own dependency tree, and its `allowBuilds` entries for packages this tree does not have
  (`esbuild`, `@posthog/cli`, `core-js`, `msedge-tts`) would approve nothing here.
- Records that keep 9.15.9 on purpose: the plan's account of decision D-S6 and its parity row,
  the 2026-11-04 audit data and the archived changes.

## Affected specs

- None. The harness stays unspecified, as decided in `2026-11-11-adopt-sdd`.
